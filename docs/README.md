## Структура вихідних файлів

```text
ripe-atlas-monitoring/
├── README.md                  головний огляд і швидкий старт
├── compose.yaml               повний новий Docker-стек
├── compose.bi.yaml            необов’язковий BI для наявного старого стека
├── .env.example               шаблон змінних без робочих паролів
├── collector/
│   ├── app/                   collector, analytics gateway та alerts
│   └── tests/                 тести обробки, агрегації й інцидентів
├── nifi/                      API-клієнт і відтворення потоку NiFi
├── clickhouse/
│   ├── init/                  початкова прикладна схема
│   └── migrations/            SQL-знімок аналітичних в’ю
├── postgres/
│   ├── init/                  епізоди, стан і доставки
│   └── migrations/            SQL-знімок операційних в’ю
├── bi/                        специфікація, JSON-експорт і тести Metabase
├── tools/                     запуск, налаштування, експорт і перевірки
├── docs/                      всі інструкції, словники та довідники
├── artifacts/screenshots/     історичні екрани аналітики
└── .github/workflows/         перевірки Git та ручне відновлення конфігурації
```

Опис кожного конкретного файла, включно з файлами в корені та вкладених папках, є у [FILES_REFERENCE.md](FILES_REFERENCE.md). Нові файли мають потрапляти і в Git, і в цей довідник.

## Де зберігаються дані та доступ

| Об’єкт | Місце зберігання |
|---|---|
| Код, Docker/SQL, налаштування NiFi та опис аналітики | Звичайні файли приватного репозиторію |
| Вимірювання, довідники й агрегати | ClickHouse у Docker-томі |
| Епізоди, операційний стан і доставки | PostgreSQL у Docker-томі |
| Налаштування та користувачі Metabase | Окрема службова PostgreSQL-БД, том metabase_data |
| Поточні файли доступу сервісів | Локальні .env та .secrets, виключені з комітів |
| Погоджена онлайн-копія .env і трьох файлів Metabase | GitHub Secrets: RIPE_CONFIGURATION_BACKUP |
| Історичні докази роботи | artifacts і bi/validation.json із зазначеними датами |

Git не містить живих Docker-томів. Нове встановлення створює схеми, а вимірювання накопичує з RIPE. Копія налаштувань відновлює паролі, а не історію даних. Приватний Git потребує дозволеного акаунта.

## Папки на комп’ютері з поточним розгортанням

`ripe-atlas-monitoring/` є основною копією вихідного коду, що синхронізується з Git. Сусідня `ripe-monitoring/` використовується попереднім робочим Docker-розгортанням: його контейнери мають bind mounts на app і backups звідти. Цю папку не можна видаляти як випадковий дублікат. Новому встановленню з основного compose.yaml друга папка не потрібна.

Локальний `ripe-atlas-monitoring-source.zip`, якщо створений поруч, є додатковим знімком відстежуваного коду. Архів `configuration-backup.zip` з Actions містить тільки конфігураційні файли з паролями. Призначення цих двох архівів різне.

## Контроль повноти

```bash
python tools/audit_documentation.py
```

Команда звіряє кожен відстежуваний файл і папку, усі описані об’єкти/стовпці БД, словник KPI, експорт дашбордів, список карток, змінні .env.example та локальні посилання. Вона не запускає Docker, не читає робочих паролів і не надсилає повідомлень. GitHub Actions повторює цю перевірку після push.
